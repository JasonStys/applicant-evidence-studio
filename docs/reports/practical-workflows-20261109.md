# Captured applicant evidence comparison — 2026-11-09

Author: Jason Stys. Baseline `a1778172437315354f70c3426e1cef1f44c2daca`. Prepared software release 0.3.0.

Added a substantial read-only human review workflow: exactly two explicitly selected authorized records, one rubric, coherent captured revisions, criterion attainment/strongest citations, alternative reviewed/excluded unreviewed claim counts, source warnings, unknown evidence, factual clarification prompts and private JSON export with transient human observations. Selection order is preserved; no winner or hire/reject outcome is produced. Education/identity/employment fields never become new scoring inputs, and no paid years/degrees are inferred.

Private accounts assemble reports solely inside their unlocked browser from one workspace clone. No plaintext endpoint, external provider call or encrypted-save request is introduced. Legacy developer mode captures input in one parameter-bound SQLite read transaction under the existing session/Host/Origin/no-cache boundary. Report output deliberately omits names/raw sources/notes/employment totals, while clearly warning that user-written evidence labels/summaries/observations can still identify people. It is unencrypted private information, not anonymized or signed evidence. Changing context/mutations/locks invalidates capture and pending asynchronous results.
